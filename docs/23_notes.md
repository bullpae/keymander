# 23. 메모·할 일·타이머 (`:m`)

> **상태:** N1~N4 구현 (2026-11-06), 실기기 확인 대기
> **코드:** `crates/kmd-core/src/notes.rs` · `notes/when.rs`(시간 읽기) · `notes/timers.rs`(타이머 상태) · `crates/kmd-daemon/src/alarms.rs`(울리기) · `crates/kmd-desktop/src/alert.rs`(알림 창) · `crates/kmd-desktop/src/app/notes.rs` · `src/tui/app/notes.rs` · `src/cmd/memo.rs`

생각나자마자 적고, 나중에 찾는다. 런처에 이미 손이 가 있으니 앱을 바꾸지 않고 적을 수 있다는 것이
다른 메모 앱과 다른 점이다.

`docs/03` 은 이 기능을 스크립트 플러그인 `kmd-memo` 로 예정했지만 플러그인 배선은 보류다(`docs/17` §3).
클립보드처럼 **네이티브로** 만든다.

## 1. 하나의 구조

메모, 할 일, 리마인더를 따로 만들지 않는다. 메모에 속성이 붙는 것이다.

| 기능 | 입력 | 실체 | 단계 |
|---|---|---|---|
| 메모 | `:m 떠오른 생각 #아이디어` | 파일 하나 | N1 |
| 할 일 | `:td 보고서 쓰기` | 메모 + `type: todo`, `done` | N2 |
| 리마인더 | `:td 보고서 쓰기 @내일 9시` | 할 일 + `due` | N3 |
| 타이머 | `:timer 10분 라면` | 저장 안 함, 데몬이 잰다 | N3 |
| 뽀모도로 | `:pomo` 또는 할 일에서 시작 | 25분/5분 타이머 반복, 횟수만 기록 | N4 |

`:t` 는 클립보드 변환이 쓰고 있어 할 일은 `:td` 다.

**일부러 뺀다:** 반복 일정, 하위 할 일, 프로젝트 보드, 캘린더 연동. 빨리 적고 찾는다는 장점이 흐려진다.
파일이 Markdown 이므로 더 필요하면 Obsidian 같은 앱이 같은 폴더를 읽으면 된다.

## 2. 저장 — 메모 하나에 파일 하나

```
<메모 폴더>/
  20261106-143012-a1b2.md      이름 = 만든 시각(지역 시간) + 임의 4자리
  .trash/20261105-090000-77c1.md
```

```markdown
---
type: todo
due: 2026-11-07T09:00
done: false
---
보고서 초안 쓰기 #업무
```

- **왜 파일 하나씩인가** — 맥과 Windows 를 클라우드 드라이브로 맞춘다. 하루 한 파일이면 두 기기가 같은 날
  적을 때마다 충돌 사본이 생긴다. 파일을 나누면 같은 메모를 양쪽에서 동시에 고칠 때만 충돌한다.
  충돌 사본도 `.md` 라 메모 하나로 보여 내용을 잃지 않는다.
- **원본은 파일이다.** 폴더의 `.md` 는 다른 앱이 만든 것도 메모로 읽는다(하위 폴더는 보지 않는다).
  시각은 이름에서 읽고, 형식이 다르면 수정 시각을 쓴다. 머리말은 N1 에서 쓰지 않지만 수정해도 그대로 지킨다.
- **폴더** — 기본 `<data_dir>/notes`(이 기기에만). `kmd memo dir <폴더>` 로 공유 폴더로 옮기고,
  `off` 로 돌아온다. 손버릇 통계의 `stats_sync` 와 나눈다 — 메모 폴더는 사람이 직접 열어 볼 곳이다.
- **정한 폴더가 없으면 만들지 않고 알린다.** 드라이브가 빠진 동안 새로 만들면 메모가 기기마다 갈라진다.
- **삭제는 `.trash/` 로 옮긴다.** 지운 것이 동기화로 모든 기기에서 사라지므로 되살릴 길을 남긴다.
  자동으로 비우지 않는다.

### 검색

FTS5 를 쓰지 않고 메모리에서 거른다. 짧은 글 수천 개라 충분하고, 파일 검색과 같은 규칙(초성, 한영 오타,
치는 중인 마지막 음절)을 그대로 쓸 수 있다. 런처는 열 때마다 새 프로세스이므로 파일을 매번 읽지 않도록
`<data_dir>/notes-index.json` 에 (수정 시각, 크기, 내용)을 둔다. 이 캐시는 기기별이고 지워도 파일에서 다시 만든다.
`:m` 에 들어올 때마다 폴더를 다시 훑어 다른 기기의 변경을 반영한다.

## 3. 런처 (N1)

| 입력·키 | 동작 |
|---|---|
| `:m 내용` Enter | 저장하고 창을 닫는다. 맨 위 행은 언제나 저장 — 비슷한 메모가 있어도 Enter 는 새 메모 |
| `:m` | 최근 메모 50개 + 안내 |
| `:m 단어` | 저장 행 아래로 맞는 메모. ↓ 로 고른다 |
| 메모 행에서 Enter | 전체 내용 복사 후 닫기 |
| Ctrl+E (⌘E) | 한 줄 메모는 입력창에서 고쳐 Enter. 여러 줄은 기본 앱으로 파일을 연다 |
| Ctrl+Del (⌘D) | 휴지통으로 |
| Ctrl+Z (⌘Z) | 이번 창에서 방금 지운 메모 되살리기 |

- 별칭: `:m` `:memo` `:메모` `:ㅡ`(한글 입력 상태의 m). `:map` 과는 토큰 경계로 갈린다.
- 고치는 중 입력을 모두 지우거나 다른 명령으로 가면 수정이 취소된다.
- 단축키는 한글 입력 상태의 낱자(`ㄷ` `ㅇ` `ㅋ`)로 와도 받는다. 메모는 한글로 쓰다 누르는 일이 많다.
- TUI 는 Ctrl+E / Ctrl+Del·Ctrl+D / Ctrl+Z 가 같고, 저장해도 닫지 않고 다음 메모를 받는다.

CLI: `kmd memo`(`kmd m`) `add <글|->` · `ls [단어]` · `show` · `edit` · `rm` · `dir [폴더|off]`.
`show`·`edit`·`rm` 은 id 또는 하나만 걸리는 단어를 받고, 여럿이 걸리면 거절한다.
여러 줄 메모는 `-`(표준 입력)나 편집기로 만든다. 입력창은 한 줄이다.

## 4. 빠른 호출과 클립보드 (N1.1, N1.2)

- CapsLock+`;` — 런처를 `:m ` 상태로 연다 (`launch:kmd-desktop --memo`). 입력 소스를 영문으로 바꾸지 않아 한글을 그대로 친다.
  런처가 이미 열려 있으면 다른 단축키처럼 닫힌다.
- `;` 목록에서 Ctrl+S (⌘S) — 고른 클립보드 항목을 메모로. 전체 글은 데몬에서 받는다(`Request::ClipText`). 데스크톱 전용이다.

## 5. 할 일 (N2)

| 입력·키 | 동작 |
|---|---|
| `:td 보고서 쓰기 @내일 9시 #업무` Enter | 저장하고 닫기. 제목은 `보고서 쓰기 #업무` |
| `:td` | 안 끝낸 일. 기한 순, 기한 없는 일은 맨 뒤(최근 것부터) |
| `:td 단어` | 저장 행 아래로 맞는 일 |
| `:td done` | 완료한 일 |
| 할 일 행에서 Enter | 완료 / 다시 할 일로. Ctrl+Z 되돌리기 |
| Ctrl+E · Ctrl+Del | 수정(`@` 시각 포함) · 삭제 |
| Ctrl+P (⌘P) | 이 일로 뽀모도로 시작 |

`:m` 목록에도 할 일이 보이고, 거기서 Enter 는 복사다. CLI: `kmd todo`(`kmd td`) `add` · `ls` · `done`.

**시간 표현**(`@` 뒤, `notes/when.rs`): `내일 9시` `오후 3시 30분` `15:30` `11/7` `11월 7일` `월요일` `다음주 금요일` `30분 뒤` `2026-11-07 09:00`.
- 날짜만 쓰면 오전 9시. 날짜가 있고 오전·오후가 없으면 1~6시는 오후(`내일 3시` = 15시).
- 시각만 쓰면 앞으로 가장 먼저 오는 때(14시에 `3시` = 오늘 15시, 16시에 `3시` = 내일 3시).
- 못 읽으면 글 그대로 저장하고 저장 행에 알린다. 공백 뒤의 `@` 만 시각으로 보므로 메일 주소는 안전하다.

## 6. 타이머·리마인더·알림 창 (N3)

- `:timer 10분 라면` Enter — 시작하고 닫기. 순서를 바꿔 `라면 10분`, 숫자만 쓰면 분(`:timer 5`).
  `:timer` 는 돌아가는 타이머 목록, Ctrl+Del 끄기, Ctrl+Z 되살리기. CLI: `kmd timer` `start` · `pomo` · `ls` · `stop`.
- **시간은 데몬이 잰다.** 런처가 끝나는 시각을 `<data_dir>/timers.json` 에 적고 데몬이 1초마다 읽는다.
  IPC 대신 파일인 이유: 데몬이 꺼져 있어도 걸 수 있고, 다시 켜지거나 잠들었다 깨면 늦게라도 울린다("12분 전에 끝났습니다").
  런처와 데몬이 모두 쓰므로 쓰기는 잠금 파일로 차례를 지킨다.
- **알림은 `kmd-desktop --alert 제목 내용 종류` 창**이다. OS 알림은 방해 금지 모드에 막히고 OS 마다 등록 절차가 다르다. 소리는 없다.
  런처 테마의 둥근 카드에 종류별 아이콘(⏱ 타이머, 🍅 집중, 🍵 휴식, 🔔 할 일)을 쓴다. 치던 글이 창을 닫지 않도록 Esc 와 클릭으로만 닫는다. 같은 자리에 뜨므로 여러 개면 겹친다.
- **리마인더는 데몬이 30초마다** 안 끝낸 일의 `due` 를 본다. 켜져 있는 모든 기기에서 울리고, 한쪽에서 완료하면 동기화 뒤 다른 쪽은 안 울린다.
  울린 기록은 기기별로 `timers.json` 에 둔다(파일에 적으면 동기화로 다른 기기 알림이 막힌다). 시각을 바꾸면 다시 울린다.
  하루 넘게 지난 일은 울리지 않고 목록에서 "기한 지남"으로 보인다 — 새 기기에서 지난 일이 한꺼번에 뜨면 안 된다. 한 번에 넷 이상이면 창 하나로 묶는다.

## 7. 뽀모도로 (N4)

- `:pomo 보고서` Enter 또는 할 일에서 Ctrl+P — 집중 25분. 끝나면 알리고 휴식 5분을 저절로 건다. 휴식이 끝나도 알리기만 하고 다음 집중은 사람이 시작한다.
- 집중은 한 번에 하나. 시간은 `[notes] focus_minutes`, `break_minutes`.
- 횟수만 남긴다 — 할 일의 머리말 `pomodoros` (`보고서 쓰기 🍅3`), 기기별 오늘 횟수는 `:pomo` 에 표시.
- 잠든 사이 휴식 시간까지 지났으면 휴식을 걸지 않는다.

## 8. 검증과 한계

유닛 테스트로 시간 읽기, 상태 파일(동시 쓰기, 남은 잠금), 끝났을 때 처리, 런처·TUI 키 흐름을 확인한다.
데몬의 울리기 루프와 알림 창은 자동 테스트가 없어 실기기 확인이 필요하다.

반복 일정은 일부러 넣지 않았다(§1).
