## 0. 이번 감사에서 확인된 강점 (건드리지 말 것)

- IPC 인증: CSPRNG 토큰 + 상수시간 비교 + 64KB 상한 + 타임아웃. 토큰 파일 0600 생성.
- 명령 실행: `Command::new + args` — shell 경유 없음, 인젝션 표면 없음.
- 키 입력·검색어를 로그에 남기는 코드 없음 (키로거화 방지).
- 검색: Nucleo + 사전 소문자화 — 이미 성능 지향.
- 자체 코드에 TODO/FIXME 마커 0건 (전부 vendor/).
- 테스트: kmd-core 171 · kmd-daemon 71 · kmd-desktop 77.

## R2-6 / R3-3 결론 (2026-09-13, 설계 결정 후 실행)

두 UI의 프리픽스 핸들러를 전수 비교한 결과, **"어느 UI가 옳다"가 아니라 항목별로
갈렸다.** 백로그의 옛 근거 하나("캐시 vs 매번 디스크 로드")는 R2-7로 이미 무효였다.
좋은 쪽을 골라 core로 올리는 방식으로 처리했다.

| 쟁점 | 채택 | 이유 |
|---|---|---|
| 결과 없음 | 데스크톱 (한글 완화 + 웹 폴백) | 빈 화면을 없앤다 |
| URL 입력 | TUI (`Open <url>` 항목) | 없으면 여는 방법 자체가 없다 |
| 빈 입력 | TUI (최근 이력) | 처음 연 사람의 유일한 학습 단서 |
| config 저장 | 데스크톱 병합 + TUI 오류 노출 | 남의 변경을 안 덮으면서 실패는 알린다 |
| 무거운 작업 | 데스크톱 (워커·세대 가드) | UI 프리즈 방지 |
| 성공/실패 알림 | **새 채널** (양쪽 상태 라인) | 이벤트를 결과 목록에 끼워 넣지 않는다 |

부수 성과 — 조사에서 드러난 사용자 피해 2건을 함께 고쳤다:
`:t`가 검색 단계에서 URL을 열어 **타이핑 중 키마다 탭이 열리던 것**(이제 실행
항목 + Enter), 데스크톱 `:emoji` Enter가 **아무것도 복사하지 않던 것**.

남은 것: 엔진 생성 3곳의 배선 통합. 동작 차이가 아니라 순수 중복이라 언제든
가능하지만 이득이 작다.
