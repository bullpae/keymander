## 1. 컨셉 — "손이 떠나면 진다"

README는 keymander가 없애려는 세 가지 **이탈**을 말한다 — 마우스로의 이탈,
홈로우로부터의 이탈, OS 사이의 이탈. dojo는 이 셋을 **요괴**로 만든다.
철학을 읽게 하지 않고, 규칙으로 체감하게 한다.

| 이탈 | 요괴 | 등장 |
|---|---|---|
| 마우스로의 이탈 (탐색기에서 헤매기) | **미아귀(迷兒鬼)** | 흰띠 관문 |
| 홈로우로부터의 이탈 (화살표 키로 손 보내기) | **화살귀(箭鬼)** 1·2·3형 | 노란·주황·초록띠 관문 |
| 한/영 키 찾아 손 옮기기 | **양설귀(兩舌鬼)** | 파란띠 관문 |
| 마우스로의 이탈 (포인팅) | **쥐마왕(鼠魔王)** | 보라띠 관문 |
| 세 이탈의 총합 | **이탈마(離脫魔)** | 갈색띠 관문 |
| OS 사이의 이탈 | **삼두마(三頭魔)** — 머리 하나가 OS 하나 | 단(段) |

세계관 장치:

- **사부(師父)** — 화면 하단 한 줄. 설계 근거를 무협 말투로 전한다. 상황 트리거로만
  말하고(§4-6), 한 화면에 한 줄을 넘지 않는다.
- **비급(祕笈) 24권** — 배치 근거 하나가 한 권. 과를 깨면 해금, 비급 시험으로 숙련.
  다 모으면 이 프로젝트의 철학 전체가 모인다 (§4-5).
- **띠** — 흰 → 노랑 → 주황 → 초록 → 파랑 → 보라 → 갈색 → 검정, 그리고 단.
- **인장(印章)** — OS마다 검은띠를 따면 찍힌다. 셋이 모이면 삼국 통일 (§8-4).

목표는 v1과 같다: **습득**(일주일 안에 몸에 붙이기), **검증**(dojo를 통과했다 =
그 기기에서 키맵이 실제로 동작한다), **전파**(결과 카드 한 장으로 공유).

## 2. 학습 설계 원칙

1. **모든 과는 "왜"에서 시작한다** — 납득 → 시연 → 반복 → 실전 → 회고.
   - 납득: 사부의 가르침 + 두 손 키보드(S4)
   - 시연: 유령 키보드(S5)
   - 반복: 대련·골프(S6~S8)
   - 실전: 가짜 앱 속 실제 작업(S9~S12)
   - 회고: 비급 카드·시험(S15~S16)
2. **적게 누르는 것이 실력이다** — 점수의 중심은 키 골프. L을 열두 번 치는 것과
   단어 점프 두 번의 차이를 점수로 가르친다.
3. **결과 키 판정** — 물리 키가 아니라 키맵이 내보낸 키를 본다(§6). 권한이 필요 없고,
   통과 자체가 키맵 동작 검증이 된다.
4. **정직 시스템** — 진짜 화살표 키를 눌러도 통과된다. dojo는 연습 도구지 시험이
   아니다. 엄격 판정은 v2 hard mode(§11).
5. **색만으로 말하지 않는다** — 모든 색 정보에 기호를 병행한다(✓ ✗ ⚑ ★ ◆ ▲).
6. **도장 자체가 수련장** — 메뉴 이동도 ↑↓, 즉 CapsLock+J/K다. 맨 `j`/`k`도
   받아 주지만, 사부가 한 번 넌지시 레이어를 권한다(맨 문자와 화살표는 구별된다).
7. **도장은 네 배치를 따르고, 비급은 표준을 가르친다** — 안내·시연·Par는 사용자의
   실제 키맵으로 다시 그린다. 비급은 기본 배치의 이치를 그대로 가르치되, 사용자의
   배치와 다르면 둘을 나란히 보여 주고 사부가 진단한다(§6-5). 진단은 꾸짖음이 아니라
   이치의 설명이고, 아무것도 잠그지 않는다.

## 3. 커리큘럼 — 띠와 과(課)

과마다 별 3개. 승급 = **그 띠의 모든 과 ★1 이상 + 관문(보스) 격파**.

| 띠 | 주제 | 과 | 관문 |
|---|---|---|---|
| ⬜ 흰띠 | **첫 60초** — 소환 → 입력 → Enter | 1 이름 몇 글자로 소환 · 2 확장자 소환 `.pdf` + ↓ · 3 의뢰 소환(소환 골프) · 4 접두 비급 `@gh` `!` | 미아귀 — 연속 의뢰 타임어택 |
| 🟨 노란띠 | **화살표 없는 화살표** — CapsLock + HJKL | 1 네 방향 · 2 미로 탈출(2D 격자) · 3 대련 | 화살귀 1형 |
| 🟧 주황띠 | **축지법** — 적게 누르기 | 1 단어 점프 I/O · 2 줄 처음/끝 II/OO(2탭 300ms) · 3 페이지 N/M · 4 지우기 `.` `/` | 축지 코스 9홀 + 화살귀 2형 |
| 🟩 초록띠 | **문서 수술** — LShift = 선택 | 1 선택의 수 · 2 선택 후 지우기 · 3 실전: 오타 세 마리 · 4 실전: 문단 손질 | 화살귀 3형 |
| 🟦 파란띠 | **한 손가락 두 얼굴** — RAlt 탭/홀드 | 1 한영 리듬 · 2 톡과 쥠의 구분 · 3 300ms 안전장치 체험 | 양설귀 — 혼합 문장 타임어택 |
| 🟪 보라띠 | **보이지 않는 마우스** — RAlt + ESDF | 1 포인터 이동(가속) · 2 조준 W/R + LShift 정밀 · 3 휠 T/G 수색 · 4 드래그 Space · 5 새는 글자 0 | 쥐마왕 |
| 🟫 갈색띠 | **레이어 불변식** — 전부 섞기 | 1 혼합 대련 · 2 비급 종합 시험(10문) · 3 실전: 홈로우를 떠나지 않는 하루(축소판) | 이탈마 |
| ⬛ 검은띠 | **졸업** | 오늘의 수련 3일 연속 (README 승급 규칙) | — |
| 🥋 단 | **삼국 통일** — One keymap, three OSes | 세 OS에서 검은띠 → 인장 3개 | 삼두마 |

과 26개 → 별 78개. 각 과의 "왜" 한 줄, 시연 수순, 홀/라운드 데이터는 콘텐츠
파일(§9)에 있고 코드에 하드코딩하지 않는다.

## 4. 게임 모드

### 4-1. 키 골프 (주황·초록띠의 핵심, 보스전의 재료)

커서를 깃발 ⚑ 까지 옮긴다(이동 홀). 또는 군더더기를 지운다(편집 홀).

- **사부의 수** = BFS로 구한 최소 타수(§7). 홀 아웃 후에 공개되고, 내 수와 나란히
  리플레이된다(S7).
- **Par** = 사부의 수 + 여유. 여유는 사부의 수가 3 이하면 1, 7 이하면 2, 그보다
  크면 3. 홀 파일에서 직접 지정해 덮어쓸 수 있다.
- 타수 = **도착한 결과 키 이벤트 수**. II(2탭 Home)는 단어← 다음 Home으로
  두 번 도착하므로 2타다(데몬 엔진이 첫 탭에 싱글 액션을 즉시 보낸다).
- 기호: ◎ 이글(-2 이하) · ◉ 버디(-1) · ─ 파 · ▲ 보기(+1) · ▲▲ 더블 이상.
  사부의 수와 같으면 ◆ 일치.
- **코스** = 9홀. 스코어카드는 실제 골프처럼(S7).

### 4-2. 대련 (반응)

제시 방향 → 결과 키로 응답. 반응시간 막대, 콤보, 최근 5회 기록(S8). 틀리면
화면이 한 칸 흔들리고(2프레임) 콤보가 끊긴다. 노란띠 반복 훈련이자 보스전의
기본 공격 단위다.

### 4-3. 실전 — 가짜 앱 속 실제 작업

- **문서 수술(S9)** — 문단 속 군더더기 글자(빨강 취소선)를 지운다. 이동 +
  `.`/`/` + LShift 선택. 타수/Par로 채점해 골프 감각을 잇는다. 초기 과는 **삭제만**으로
  풀리는 오타만 낸다(한글 입력 조합을 판정에 끌어들이지 않기 위해).
- **다이얼로그** — `저장하시겠습니까? [예] [아니오]` 의 "아니오"를 마우스 레이어로.
- **드래그** — 파일 아이콘을 폴더로(Space 홀드).
- **스크롤 수색** — 긴 목록에서 T/G 휠로 항목 찾기.
- **한영 리듬(S11)** — `kmd 로 PDF 를 찾는다` 같은 혼합 문장. 전환 지점에서 RAlt 톡.

### 4-4. 소환술 — 런처 골프 (S12)

의뢰("지난달 받은 견적서 PDF를 열어 달라")를 읽고 **최소 입력으로 목표를
1순위에 올려 Enter**. 판정은 kmd-core `SearchEngine`을 그대로 쓴다.

- **연습 목록(기본)** — 내장 가짜 인덱스(앱·파일·폴더 ~200개, 날짜·확장자 다양).
  결정론적이라 Par가 공정하다.
- **도장 밖 실전(선택)** — 실제 인덱스. 의뢰는 **내 실행 기록**(`history` 테이블)에서
  뽑는다("어제 연 그것을 다시 소환하라"). 기록이 적으면(<10건) 켤 수 없다.
- 타수 = 입력 글자 + ↓ 이동 + Enter. 사부의 수 = 목표가 1순위가 되는 **가장 짧은
  쿼리**(§7-4).

### 4-6. 사부 대사 트리거

| 트리거 | 예 |

| 사부의 수 일치 | "◆ 나와 같은 수다." |

### 4-7. 일일 수련

2분짜리. 날짜를 시드로 해금된 콘텐츠에서 골프 3홀 + 대련 1 + 소환 1을 뽑는다.
완주한 날이 **연속 수련일**이 되고, 3일 연속이 검은띠 조건이다.

## 5. 화면 설계 (UI/UX)

### 5-1. 공통 규칙

- **크기** — 최소 80×24. 더 크면 80칸 고정 폭을 가운데에 둔다(넓어져도 시선
  이동이 늘지 않게). 미달이면 "창을 키워라 (지금 72×20)" 한 화면만 보인다.
- **프레임** — 1행 머리줄(브랜드 · 현재 위치 / 오른쪽: 띠·진행), 맨 아래 1행 키 안내줄.
  본문은 그 사이 22행.
- **조작** — 메뉴: ↑↓ 이동(=CapsLock+J/K), ←→ 탭/띠 이동, Enter 선택, Esc 뒤로.
  라운드: **Esc = 일시정지, 일시정지 중 Esc = 그만두기**. `Ctrl+C`는 종료 키가 아니다
  (raw mode 라 SIGINT도 아니고, Ctrl 계열이 판정에 쓰일 수 있다).
- **색의 의미는 고정** — 파랑 = 쥐는 손, 주황 = 움직이는 손, 초록 = 성공·깃발,
  빨강 = 실패·군더더기, 금색 = 별·비급·사부, 반전 = 커서. 띠 색은 띠 표시에만.
- **피드백 시간** — 정답: 120ms 초록 플래시. 오답: 빨강 + 가로 1칸 흔들림 2프레임.
  콤보 숫자는 갱신 시 1프레임 굵게. `dojo.reduce_motion = true`면 흔들림·승급
  애니메이션을 끄고 정지 화면으로 대신한다.
- **입력기** — 한글 자모/음절이 도착하면(한영 리듬 과 제외) 즉시 상단 배너
  "영문으로 — RAlt 톡". IME 조합 중 글자가 입력 위치에 보이도록 실제 터미널 커서를
  입력 칸에 둔다(`Frame::set_cursor_position`).
- **렌더 주기** — 이벤트 기반. 애니메이션이 있을 때만 30fps tick, 없으면 250ms
  대기. 키 훅 데몬이 도는 동안 CPU를 태우지 않는다(사고 수칙 — 키보드 먹통 건).
- **저색상 터미널** — 256색 미만이면 RGB 대신 기본 16색 팔레트로 폴백(F17과 공유).

#### S9. 실전 — 문서 수술

가짜 앱 속 실제 작업. 군더더기 글자(빨강)를 nav 이동과 . / 삭제, LShift 선택으로 제거한다. 실전도 타수/Par 로 채점해 골프 감각을 이어간다.

## 6. 판정 아키텍처

### 6-1. 결과 키 판정 (v1 결정 유지)

CapsLock+H를 누르면 키맵이 Left를 보내고, 터미널에는 Left가 도착한다. crossterm이
`KeyCode::Left`를 받으면 성공. 물리 입력 후킹이 없으니 권한 문제가 없고, 통과
자체가 키맵 동작 검증이다.

판정은 **도착 이벤트 → 수(Action)** 로 한 번 번역한 뒤 이루어진다.

```text
crossterm Event ──(보정 표 calib)──▶ Action { Left, Down, Up, Right, WordLeft, WordRight,
                                              LineStart, LineEnd, PageUp, PageDown,
                                              Backspace, Delete, + Shift 변형 }
                                     ──(judge, 순수 함수)──▶ 판정 / 상태 전이
```

### 6-2. 입문 의식 — 키 감응 보정 (S2)

**문제** — 같은 수라도 OS·터미널마다 다른 이벤트로 도착한다.

| 수 | 데몬이 보내는 키 | 터미널에 도착하는 예 |
|---|---|---|
| 단어← (macOS) | `Alt+Left` | iTerm2 기본 `Alt+Left` / "Natural Text Editing" 프리셋 `ESC b` = `Alt+'b'` / Terminal.app `ESC b` |
| 줄 처음 (macOS) | `Cmd+Left` | iTerm2 Natural `Ctrl+A` / Terminal.app **전달 안 됨** |
| 단어← (Win/Linux) | `Ctrl+Left` | 대개 `Left + CONTROL` |
| 줄 처음 (Win/Linux) | `Home` | 대개 `Home` |

**해법** — 12개 수를 하나씩 요청하고, 실제로 도착한 이벤트를 기록한다.

- 내장 **기본 별칭표**(위 표의 흔한 경우)가 있어 대부분은 "확인"만으로 끝난다.
- 5초 안에 아무것도 오지 않으면 **관측 불가**. 그 수는 이 터미널의 허용 수에서
  빠지고, 골프 Par는 그 수 없이 다시 계산된다(S6 "관측 불가" 줄). 관측 불가가 있는
  과는 사유를 표시하고 잠기지 않는다 — 다른 수로 풀 수 있으면 풀게 둔다.
- 첫 수(H)부터 10초 동안 아무것도 오지 않으면 진단 화면: 키맵이 꺼졌거나, macOS에서
  다른 프로세스가 **보안 입력(Secure Input)** 을 쥐고 있을 수 있다는 안내와 함께
  `kmd keymap status`를 권한다.
- 저장: `kv_store` 의 `dojo.calib.<터미널 식별자>` (JSON). 식별자 = `TERM_PROGRAM`
  → `WT_SESSION` 유무(Windows Terminal) → `TERM` 순.

### 6-3. 사전 점검

1. **키맵 활성** — `kmd_core::keymap::is_running()`(kanata) 또는 데몬 IPC 상태.
   비활성이면 노란띠 이상 잠금 + "지금 켜기"(`kmd keymap start` 제안).
2. **마우스 캡처** — crossterm `EnableMouseCapture`(1000/1002/1003/1006).
   진입 후 3초 안에 `Moved` 이벤트가 하나도 없으면 "포인터 움직임 보고 미지원" →
   보라띠는 **클릭 좌표만으로** 판정하는 축소 모드로 진행.
3. **입력기** — 한글 모드 감지 시 경고(S2).
4. **크기** — 80×24 미만이면 대기 화면.
5. **Windows 레거시 콘솔(conhost)** — 색·마우스가 불안정하므로 Windows Terminal을 권하고
   보라띠를 잠근다(`win_console::is_modern_terminal` 재사용).

### 6-4. 모드별 판정

| 모드 | 판정 |
|---|---|
| 대련 | 도착 Action == 제시 Action. 반응시간 = 제시 → 도착 |
| 골프·실전 | Action을 에디터 모델(§7)에 적용, 깃발 도달 / 군더더기 전부 제거 시 홀 아웃 |
| 미로 | 2D 격자 위 4방향 Action |
| 한영 리듬 | 도착 글자의 문자 체계(한글 음절·자모 / 라틴)가 제시 문장과 일치하는지. 조합 중 글자는 확정될 때 도착하므로 확정 글자만 본다 |
| 조준·드래그 | `MouseEvent{Down(Left/Right), column, row}`가 과녁 상자 안인지. 드래그 = `Down → Drag… → Up`의 시작/끝 좌표 |
| 휠 | `ScrollUp/ScrollDown` 누적으로 목록 이동 |
| 새는 글자 0 | RAlt를 쥔 채 마구 친 5초 동안 `Key` 이벤트 0건 = 통과 (마우스 레이어 `unmapped = block` 검증) |
| 소환술 | 쿼리 → `SearchEngine::search` → 목표가 1순위인 상태에서 Enter |

라운드 중에는 nav 레이어 `Space`(=놓을 때 kmd-desktop 실행)를 수로 요구하지 않고,
첫 입장 때 "라운드 중 CapsLock+Space 는 런처가 뜬다" 고 한 번 알린다.

### 6-5. 사용자 키맵 반영 — 수(Action) 중심 설계

사용자는 트리거를 LAlt로 되돌리거나, 키를 옮기거나, 수를 지울 수 있다(config의
`[launcher.keymap]` 레이어 덮어쓰기). 이때 무엇이 영향을 받는지 나누면 이렇다.

| 영역 | 영향 | 이유 |
|---|---|---|
| **판정** | 없음 | 결과 키를 보므로, 단어←를 어느 물리 키에 두든 `Ctrl+Left`가 도착하면 통과 |
| **안내 문구 · 두 손 키보드 · 유령 시연** | **틀려진다** | "CapsLock + K"가 하드코딩이면 LAlt 사용자에게 거짓말 |
| **허용 수 · Par** | **틀려진다** | 페이지 수를 지운 사용자에게 N/M을 쓰는 사부의 수는 불가능한 기준 |
| **입문 의식 요청** | **틀려진다** | "CapsLock 을 쥐고 I" 대신 그 사용자의 키를 요청해야 한다 |
| **비급** | 의미가 갈린다 | 표준의 이치를 가르치는데, 사용자의 배치는 그 이치를 어길 수 있다 |

**원칙: 콘텐츠는 키가 아니라 수로 쓴다.** 과·시연·홀·대사는 `{WordLeft}`처럼 수를
가리키는 자리표시자만 쓰고, 화면에 그리는 순간 **배치 해석기(binding resolver)** 가
물리 키로 바꾼다.

```text
config ──▶ effective_keymap()  ──▶ resolver ──▶ Action → Binding { 트리거, 키, 탭 횟수, 출처 }
           (데몬·치트시트와 같은                   │
            단일 소스, 새로 만들지 않는다)            ├─▶ 안내 문구·키보드 강조·시연 수순
                                                   ├─▶ 허용 수 집합 (보정 결과와 교집합) ──▶ Par
                                                   ├─▶ 입문 의식 요청 목록
                                                   └─▶ 배치 진단 (S19)
```

- **해석 규칙**
  - 레이어 `mappings`의 대상 문자열을 OS별 별칭표로 수에 대응시킨다. 예: macOS
    `Alt+Left` = 단어←, Win/Linux `Ctrl+Left` = 단어←, `Home` / macOS `Cmd+Left` = 줄 처음.
  - `double_taps`의 single은 1탭 수, double은 2탭 수가 된다. II처럼 2탭 수는 2타다.
  - mouse 레이어의 포인터·클릭·휠, `tap_action = "Hangul"`과 `Shift+Space` 콤보는
    한/영 수로 읽는다.
  - 대상이 수가 아닌 매핑(예: `P = "Ctrl+V"`)은 수 목록에는 없고 진단에만 쓴다.
  - 한 수에 바인딩이 여러 개면 레이어 → 리맵 순으로 고르고, 표준 키가 그중에 있으면 그것을 고른다.
- **수가 없을 때** — 그 수는 "미보유"가 된다. 보정의 "관측 불가"와 같은 경로로 허용
  수에서 빠지고 Par를 다시 계산한다. 그 수가 주제인 과(예: 페이지 N/M 과)는 "네
  배치엔 이 수가 없다 — 비급만 읽을 수 있다"로 표시하고 **승급 조건에서 뺀다**. 잠그지 않는다.
- **배치 지문(fingerprint)** — 수 → 바인딩 표를 정규화해 해시한다. config의 무관한
  항목이 바뀌어도 지문은 그대로다.
  - 저장: `kv_store`의 `dojo.keymap_fp`. 기록(`dojo_runs.keymap_fp`)에도 남긴다.
  - 지문이 바뀌면 다음 입장 때 S19(배치 진단)를 띄우고 입문 의식 재실행을 권한다.
  - 예전 기록은 지우지 않고 "다른 배치에서의 기록" 표식만 붙인다. 별도 그대로 둔다.
- **다시 읽는 시점** — 지도·과 입문 화면에 들어갈 때 config 파일 mtime을 보고 바뀌었으면
  다시 해석한다. 파일 감시자는 두지 않는다(유휴 CPU 0 유지).
- **백엔드별 신뢰도**

  | 백엔드 | 배치 출처 | 표시 |
  |---|---|---|
  | 내장 데몬 (Win/macOS) | `effective_keymap()` — 엔진이 실제로 쓰는 것과 동일 | 전체 기능 |
  | kanata + 내장 프리셋 원본 그대로 | 프로필 파일 내용 == `preset_content()`이면 같은 이름의 `effective_keymap()` | 전체 기능 |
  | kanata + 직접 고친 `.kbd` | 해석 불가 | **배치 미상 모드** — 키 대신 수 이름("단어← 수")으로 안내하고, 키보드 다이어그램과 진단은 끈다. 판정과 보정은 그대로 동작 |

  두 번째 행이 성립하려면 내장 `vim-nav.kbd`와 `vim_nav_default_layer()`가 같은 배치여야
  한다. 이를 **동등성 테스트**로 고정한다. 어긋나면 그 자체가 "One keymap" 약속을
  어기는 버그이므로, dojo가 이 테스트를 데려오는 것은 덤 이상의 가치가 있다.
  의도된 OS 차이(macOS Cmd 계열)는 테스트에서 OS별로 허용한다.

**배치 진단 — 비급과 배치가 만나는 곳(S19)**

사용자 배치에 비급의 이치를 규칙으로 적용해 본다. 규칙 하나가 비급 한 권이다.

| 규칙 | 비급 | 등급 | 예 |
|---|---|---|---|
| 레이어 트리거와 그 레이어 매핑 키의 과반이 같은 손 | 卷一 두 손의 법칙 | 경고 | 트리거 `RAlt` + 이동 `HJKL` (둘 다 오른손) |
| 레이어 매핑 대상이 되돌릴 수 없거나 내용을 바꾸는 수 (붙여넣기·잘라내기·Enter·매크로) | 卷四 레이어 불변식 | 경고 | nav `P = Ctrl+V` |
| 최빈 삭제 키 옆 칸에 파괴적 수 | 卷七 완충지대 | 경고 | nav `, = Ctrl+Backspace` |
| 레이어 트리거가 modifier | 卷九 CapsLock 승격 | 정보 — 대가를 설명 | `LAlt` 트리거: 앱의 Alt 단축키를 가리지만 HHKB 모드탭이 살아난다 |
| 포인터 이동이 WASD | 卷十三 ESDF 의 이치 | 정보 | mouse `W/A/S/D` |
| 지켜진 이치 | 해당 권 | 칭찬 | "쥐는 손과 움직이는 손이 다르다 ✓" |

- 경고도 아무것도 막지 않는다. 비급 카드에서 해당 권을 열면 "표준 / 네 배치"가 나란히 보인다.
- 사람 손 구분(왼손/오른손)은 ANSI 표준 운지표(docs/16 §2)를 쓴다.

## 7. 골프 엔진

### 7-1. 에디터 모델 (`golf/buffer.rs`)

- 버퍼 = 줄 목록, 커서 `(row, col)` + **sticky col**(↑↓ 이동 시 원래 열 기억).
- 이동 규칙은 일반 OS 텍스트 필드를 따른다:
  - ←→는 줄 경계를 넘는다(줄 처음에서 ← = 윗줄 끝).
  - ↑↓는 sticky col을 쓴다.
  - Home/End는 줄 처음/끝이다(smart home 없음).
  - PgUp/PgDn은 홀이 정한 페이지 높이(기본 10줄)만큼 움직인다.
- **단어 경계는 OS를 따른다** — 사용자가 실제 앱에서 겪는 감각과 같아야 한다.
  - Windows: `Ctrl+→` = 다음 단어의 **시작**.
  - macOS · Linux(GTK): `Alt/Ctrl+→` = 현재/다음 단어의 **끝**.
  - ←는 양쪽 모두 단어 시작.
  - 단어 = 영숫자·`_`·한글의 연속. 그 밖의 문자는 구분자다.
- 편집: Backspace, Delete, Shift+이동 = 선택(anchor), 선택 중 BkSp/Del = 선택 삭제.
- 한글은 화면에서 2칸이지만 커서는 **글자 단위**로 움직인다(렌더만 폭을 안다).

### 7-2. 사부의 수 — BFS (`golf/par.rs`)

- **이동 홀**: 상태 = `(row, col, sticky)`, 간선 = 허용 Action(보정 결과 반영).
  간선 비용은 1이고, II/OO처럼 2이벤트로 도착하는 수는 2다. 버퍼가 작아서(≤ 40줄)
  전수 BFS로 충분하다.
- **편집 홀**: 군더더기 ≤ 4개.
  - 군더더기 순서의 모든 순열(≤ 24)마다 "다음 군더더기까지 이동 BFS + 제거 비용 최소값
    (`n×Del` / `n×BkSp` / Shift 선택 + 1회 삭제)"을 더한다.
  - 지운 뒤 뒤쪽 좌표는 오프셋을 보정한다.
  - 제거 비용은 경우가 적어 국소적으로 정확하다. 순열 합의 최소값을 사부의 수로 쓴다.
- 리플레이용으로 최적 경로(Action 열)도 같이 반환한다.

### 7-3. 홀 데이터 검증 (테스트)

모든 홀은 테스트로 전수 검증한다.

- 깃발에 도달할 수 있어야 한다.
- 사부의 수 ≥ 1.
- Par 지정값 ≥ 사부의 수.
- 기본 허용 수만으로도 풀려야 한다 — 관측 불가 상황에서도 hjkl만으로 풀린다.

### 7-4. 소환 골프의 사부의 수

목표 항목 이름에서 후보 쿼리를 길이 오름차순으로 만들어 처음으로 1순위가 되는
것을 찾는다.

- 후보 쿼리: 이름의 접두사, 단어 머리글자 조합, 연속 부분 문자열, `.확장자`.
- 사부의 수 = 쿼리 길이 + 1 (Enter).
- 길이 6에서 상한을 두고, 그때까지 1순위가 안 되면 "↓ k번" 경로까지 포함해 최소값을 쓴다.
- 연습 목록은 빌드 시 고정이므로 이 값을 테스트에서 미리 검증한다.

## 8. 점수 · 별 · 승급

### 8-1. 별

| 모드 | ★ | ★★ | ★★★ |
|---|---|---|---|
| 골프 코스 / 실전 | 완주 | 합계 ≤ Par | 모든 홀 파 이하 + ◆ 일치 홀 ≥ 절반 |
| 대련 | 완주 · 정확도 ≥ 70% | 정확도 ≥ 90% · 평균 ≤ 기준 | 무실수 · 평균 ≤ 기준 × 0.8 |
| 소환술 | 완주 | 합계 ≤ Par | 모든 의뢰 사부의 수 |
| 조준 | 명중 ≥ 7/10 | 10/10 · 시간 ≤ 기준 | 10/10 · 정밀 과녁 무실수 · 시간 ≤ 기준 × 0.8 |
| 보스 | 격파 | 남은 기 ≥ 50% | 남은 기 ≥ 80% |

- 힌트를 쓰면 그 과는 최대 ★★다.
- 반응 기준값은 M2에서 자체 플레이로 보정한 뒤 상수로 고정한다(점수 인플레이션 방지).

### 8-2. 승급

띠의 모든 과 ★1 이상 → 관문 해금 → 격파 → 승급식(S14, 새 비급 1권).
검은띠는 갈색띠 + 일일 수련 3일 연속.

### 8-3. 보스전

그 띠의 수를 섞은 공격 10회(대련 + 미니 홀).

- 명중하면 보스 HP가 줄어든다. 미니 홀은 파 이하면 명중이다.
- 실수하면 내 기(氣)가 줄어든다. 보기는 −10%, 오답은 −15%.
- 기가 0이 되면 패배하고, 다시 도전할 수 있다.
- 보스전 중 일시정지는 1회만 쓸 수 있다.

### 8-4. OS 인장

- 기기마다 DB가 따로이므로 인장을 **코드로 옮긴다**.
- 내보내기: `kmd dojo seal export`. 출력은 `KMD1-` + base32(JSON{os, belt, 달성일}) + CRC.
- 가져오기: 다른 기기에서 `kmd dojo seal import <코드>`. 인장이 합쳐진다.
- CRC는 오타 검출용일 뿐이다. 위조 방지는 하지 않는다 — 정직 시스템.

## 9. 콘텐츠 — 코드가 아니라 데이터

`assets/dojo/` 아래 TOML을 바이너리에 `include_str!`로 내장한다(단일 바이너리 원칙).

```text
assets/dojo/
  curriculum.toml     # 띠·과·관문, 해금 조건, 각 과의 "왜" 한 줄과 시연 수순
  scrolls.toml        # 비급 24권: 제목, 본문, 원전, 시험 문항
  sensei.toml         # 트리거별 대사 후보 (무작위 1줄)
  holes/*.toml        # 골프·실전·미로 홀
  summon.toml         # 소환술 연습 목록 + 의뢰
```

```toml
# holes/jump.toml
[[hole]]
id     = "jump-03"
course = "축지"
moves  = ["hjkl", "word", "line", "page"]   # 이 홀에서 허용하는 수 묶음
par    = "auto"                              # 또는 정수로 덮어쓰기
start  = [0, 0]
flag   = [2, 16]
text   = """
fn main() -> Result<()> {
    let config = load_config()?;
    let index = build_index(&config);
    run(index)
}
"""
```

문구에는 물리 키를 쓰지 않는다. 수 자리표시자만 쓰고, 렌더 시점에 배치 해석기가 채운다(§6-5).

```toml
# curriculum.toml 의 한 과
[[lesson]]
id    = "orange.1"
title = "단어 점프"
why   = "{WordRight} 두 번이면 {Right} 열두 번이 필요 없다."   # → "CapsLock+O 두 번이면 …"
demo  = ["WordRight", "WordRight", "WordLeft"]                 # 시연도 수의 열
needs = ["WordLeft", "WordRight"]   # 이 수가 미보유면 과를 승급 조건에서 뺀다
scroll = "五"
```

로더 테스트가 모든 TOML을 파싱하고 §7-3 검증과 상호 참조를 확인한다.
문구에 물리 키 이름(`CapsLock`, `LAlt` …)이 직접 들어가면 테스트를 실패시킨다.
예외는 비급의 "표준 배치" 서술이다.
상호 참조란 과 → 홀 id, 과 → 비급 id, 비급 → 원전 경로다.

## 10. 데이터 — DB 마이그레이션 v5

`kmd-core/src/db.rs`의 `migrate()`에 v4 → v5 단계를 추가한다.

```sql
CREATE TABLE dojo_runs (
  id INTEGER PRIMARY KEY,
  lesson TEXT NOT NULL,            -- 'orange.2', 'boss.yellow' …
  kind TEXT NOT NULL,              -- golf | spar | surgery | mouse | ime | summon | boss | daily
  strokes INTEGER, par INTEGER,    -- 골프류만
  score INTEGER NOT NULL,
  stars INTEGER NOT NULL,          -- 0~3
  max_combo INTEGER, mistakes INTEGER NOT NULL DEFAULT 0,
  hints INTEGER NOT NULL DEFAULT 0,
  duration_ms INTEGER NOT NULL,
  os TEXT NOT NULL, terminal TEXT,
  keymap_fp TEXT,                  -- 배치 지문 (§6-5). 다르면 "다른 배치에서의 기록"
  created_at INTEGER NOT NULL
);
CREATE TABLE dojo_progress (       -- 과별 최고 기록 (지도 화면용 캐시)
  lesson TEXT PRIMARY KEY, best_stars INTEGER NOT NULL,
  best_score INTEGER, best_strokes INTEGER, cleared_at INTEGER
);
CREATE TABLE dojo_scrolls (scroll TEXT PRIMARY KEY, unlocked_at INTEGER NOT NULL,
                           mastery INTEGER NOT NULL DEFAULT 0);
CREATE TABLE dojo_daily  (day TEXT PRIMARY KEY, score INTEGER NOT NULL,
                          completed_at INTEGER NOT NULL);       -- 'YYYY-MM-DD' 로컬
CREATE TABLE dojo_seals  (os TEXT PRIMARY KEY, earned_at INTEGER NOT NULL,
                          source TEXT NOT NULL);                -- local | imported
CREATE TABLE dojo_keys   (action TEXT PRIMARY KEY, count INTEGER NOT NULL); -- 많이 쓴 수
```

보정 결과는 `kv_store`(§6-2). 띠는 `dojo_progress`에서 계산하고 저장하지 않는다
(진실 소스 하나).

- **CLI**
  - `kmd dojo [--lesson <id>] [--calibrate]`
  - `kmd dojo card`
  - `kmd dojo seal export|import <코드>`
- **TUI 런처** — `:dojo`를 `query_prefix::COMMANDS` 레지스트리에 한 항목으로 추가한다.
  Enter 시 런처 터미널 세션을 내려놓고 `run_dojo()`로 넘어갔다가, 끝나면 돌아온다.
- **Desktop** — `:dojo`는 터미널에서 `kmd dojo`를 실행한다. Desktop 안에 게임을 넣지 않는다
  (창 하나, 코드 한 벌).
- **테스트**
  - judge / score / buffer / par / calib는 순수 함수 단위 테스트다(keybind 엔진 테스트 스타일).
  - 화면은 ratatui `TestBackend`로 80×24 렌더 스모크를 돌린다: 패닉이 없어야 하고,
    폭이 넘치면 안 된다.

## 13. 리스크 · 작업 수칙

- **터미널 편차** — 보정 의식(§6-2)이 1차 방어선이다. M2 완료 조건에 3터미널 스모크를 넣는다.
- **Terminal.app의 Cmd+Left 미전달** — 줄 처음/끝이 관측 불가가 된다. Par는 그 수를
  빼고 다시 계산하고, 사유를 표시한다.
- **포인터 움직임 미보고 터미널** — 클릭 좌표만 쓰는 축소 판정(§6-3).
- **IME 조합 표시 위치** — 실제 커서를 입력 칸에 둔다. 조합 중 글자는 판정하지 않는다.
- **CPU** — 이벤트 기반 렌더, 유휴 시 250ms 대기. 키 훅이 도는 동안 바쁜 루프를 금지한다.
  개발 중 빌드도 한 번에 하나씩 돌린다(키보드 먹통 사고 수칙).
- **CapsLock+Space** — 라운드 중 런처가 뜰 수 있다. 수로 요구하지 않고 첫 입장 때 알린다.
- **정직 시스템의 한계** — 진짜 화살표나 Shift 대문자로도 통과된다. 수용하고, v2 hard mode로 보강한다.
- **직접 고친 kanata `.kbd`** — 배치를 해석할 수 없다(Linux는 kanata가 유일한 경로라 영향이 크다).
  배치 미상 모드로 수 이름 안내를 하고, 보정이 실제 도착을 검증한다. kbd 부분 파서(`deflayer`
  매핑만)는 수요를 보고 후속으로 검토한다.
