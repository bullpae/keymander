# 21. `:say` — 컴퓨터 앞에서 영어에 스며들기 (입버릇 데스크톱)

> 상태: **S1 구현** (2026-10-25, 브랜치 `bullpae/say`) — 런처 카드·`:say` 타이핑 연습·담기/가져오기/내보내기·`kmd say`. S2~S4 남음.
> 코드: `crates/kmd-core/src/say/`, 데스크톱 `crates/kmd-desktop/src/app/say.rs`. 원본 앱: [bullpae/SayHabit](https://github.com/bullpae/SayHabit) (입버릇, Expo, 서버 없음)
> 관련: [10_dojo_plan.md](10_dojo_plan.md)(수련 틀). 손버릇 통계(docs/19, `bullpae/dojo`)의 공유 폴더 비교가 동기화 선례다.

## 1. 왜

입버릇은 "하루 속에 흩어진 반복"으로 영어 문장을 입버릇으로 만든다. 그런데 하루 중
가장 오래 앉아 있는 곳은 컴퓨터 앞이고, 거기서는 폰 알림을 잘 안 본다.

컴퓨터에서 입버릇을 그대로 따라 하면(무작위 알림 → 소리 내어 말하기) 일의 흐름만 끊는다.
그래서 컴퓨터에서는 역할을 나눈다.

| | 폰 (입버릇) | 컴퓨터 (`:say`) |
|---|---|---|
| 주 역할 | **말하기** — 말해야 통과 | **노출** — 일하는 흐름 안에서 자주 보고 듣기 |
| 보조 역할 | | 떠올리기(타이핑), 문장 **수집** |
| 언제 | 무작위 알림 | 런처를 열 때마다, 손이 쉬는 틈 |
| 복습 상자(box)를 올리나 | 올린다 (통과) | **올리지 않는다** — 미루기만 한다 (§4) |

> 한 줄 콘셉트: **컴퓨터는 영어를 자주 보여 주고, 폰은 입으로 굳힌다.**

keymander가 이 일에 맞는 이유:

- 런처는 하루 수십 번 뜬다 → 따로 창을 띄우지 않아도 노출 기회가 생긴다.
- 데몬은 키보드 흐름을 보고 있다 → 무작위 시각이 아니라 "손이 쉬는 틈"을 고를 수 있다.
- 문장을 만나는 곳(문서, 메일, 번역)이 컴퓨터다 → 수집이 쉽다.

## 2. 노출 지점 (많이 보이는 순)

### 2.1 런처 한 줄 카드 — 기본 노출 (S1)

CapsLock+Space로 런처를 열면, 입력이 비어 있을 때 결과 목록 **아래**에 한 줄이 붙는다.

```
 🕘 최근: Visual Studio Code
 🕘 최근: ~/work/report.docx
 ─────────────────────────────────────────────
 💬 I'm running a bit late.   조금 늦을 것 같아요        (노출 단계)
 💬 조금 늦을 것 같아요  →  ?   Tab: 보기                (떠올리기 단계)
```

- **목록 항목이 아니다.** 선택되지 않고 Enter를 가로채지 않는다. 최근 항목을 Enter로 여는 습관을 깨지 않는다.
- 단계는 입버릇과 같다. box<2는 영어와 한국어를 같이(노출), box≥2는 한국어만(떠올리기).
- 떠올리기 단계에서 빈 입력일 때 `Tab`을 누르면 영어가 열린다(S2부터 소리도). Tab 은 `:scope` 자동완성에만 쓰여 빈 입력에서는 겹치지 않는다.
- 최근 실행 항목이 하나도 없으면(처음 설치) 상태 줄이 안 보이므로 카드를 목록 항목으로 넣는다. 이때 Enter = `:say` 연습.
- 한 글자라도 치면 카드가 사라진다. 검색이 먼저다.
- 어떤 문장을 보여 줄지: 복습할 때가 된 문장 중 최근 3개를 뺀 것(입버릇 `pickForTime` 규칙). 같은 문장은 10분 동안 그대로 둔다. 런처를 열 때마다 바뀌면 읽기 전에 넘어간다.
- 런처는 단축키마다 새 프로세스라 "10분 고정"과 "최근 3개"는 `state.json` 에 둔다. 노출 수(`seenCount`)는 창 하나에 한 번 세고, 첫 화면을 늦추지 않게 뒤에서 쓴다.

### 2.2 `:say` 명령 — 의도한 연습 (S1)

```
:say                 연습 — 지금 복습할 문장 하나 (빈 입력 Enter = 정답 보기)
:say <영어>           답 — 점수 미리보기, Enter = 채점
:say add             클립보드의 문장 담기 ("English | 한국어" 이면 바로, 영어만 있으면 `:say add <영어> | ` 로 바꿔 뜻을 적게 한다)
:say add I'm on it | 지금 하고 있어요
:say import          클립보드의 여러 줄을 한 번에 (입버릇 일괄 붙여넣기 형식 그대로)
:say export          전체를 "English | 한국어" 줄로 클립보드에 → 폰 입버릇 일괄 붙여넣기
:say list            모은 문장 (복습 순) — Enter = 그 문장으로 연습
:say stats           상자별 개수, 본 횟수·타이핑 통과·폰에서 말한 횟수
:say next            채점 없이 다른 문장으로
:say on / off        켜기·끄기 (문장은 남는다)
```

하위 명령은 **그 낱말 하나만** 있을 때(`add` 는 `|` 가 있을 때도) 하위 명령이다. `:say add me to the meeting` 처럼 낱말로 시작하는 답도 답으로 채점된다.

연습 화면(타이핑 떠올리기):

1. 한국어를 보여 준다(노출 단계 문장은 영어도 같이). 영어를 친다.
2. 입버릇의 채점 함수(`scoring.ts`를 옮긴 것)로 점수를 낸다. 빠진 단어는 `[a]` 처럼 괄호로 표시한다(결과 행은 색을 못 입힌다). 떠올리기 단계에서는 답을 알려 주는 셈이라 맞은 단어 수만 보인다.
3. 기준 점수(기본 0.8)를 넘으면 다음 문장으로 넘어간다(S2부터 정답을 들려준다).
4. 틀리면 정답을 보여 주고 그 문장을 붙잡아 둔다. 한 번 따라 치면 넘어간다 — 따라 치기는 일정을 바꾸지 않는다.

`:say` 는 한영 전환 없이 영문 자판으로 바로 칠 수 있다. 한글 별칭 `:입버릇` 도 둔다.

### 2.3 소리 — 듣기 노출 (S2)

- OS 내장 음성을 쓴다. macOS는 `say -v Samantha`, Windows는 SAPI(PowerShell, 콘솔 숨김). 새 의존성이 없다.
- 소리가 나는 때: 카드에서 Tab으로 영어를 열 때, 연습에서 통과했을 때. **그 외에는 저절로 소리를 내지 않는다** — 사무실과 회의를 생각한 기본값이다.
- 속도는 입버릇의 `speechRate` 설정과 같은 뜻으로 쓴다.

### 2.4 틈 알림 — 손이 쉴 때 한 번 (S3)

입버릇은 무작위 시각에 알림을 보낸다. 컴퓨터에서는 **틈**을 고른다.

- 틈의 정의: 5분 넘게 계속 타이핑하다가 60초 넘게 키 입력이 없을 때. 빌드나 테스트를 걸어 두고 손을 뗀 순간이 여기에 걸린다.
- 횟수: 하루 최대 6번(입버릇 `perDay` 기본값과 같음), 알림 사이는 최소 45분.
- 시간대: 입버릇과 같은 `startHour`~`endHour`(기본 9~22시).
- 띄우지 않을 때: 보안 입력 중, 앞 창이 전체 화면일 때(발표, 영상), 방해 금지 모드일 때, 오늘 이미 런처 카드로 그 문장을 본 경우.
- 모양: 화면 구석에 런처와 같은 모양의 작은 카드를 포커스를 뺏지 않고 띄운다. 8초 뒤에 사라진다. 단축키 한 번이면 `:say` 연습이 그 문장으로 열린다.
- 데몬은 "틈이 났다"만 판단한다. 카드를 그리는 것은 데스크톱이 한다.
- macOS 시스템 알림(알림 센터)은 쓰지 않는다. 앱 번들이 아닌 데몬에서 보내면 출처가 이상하게 붙고 권한 창이 또 뜬다.

### 2.5 하지 않는 것

- 잠금 화면, 바탕 화면, 메뉴 막대 상주: 런처 카드와 겹치고 OS마다 따로 만들어야 한다.
- 번역(`@tr`) 결과 자동 수집: 번역은 웹 페이지로 넘기므로 keymander가 결과를 모른다. 번역 결과를 복사한 뒤 `:say add` 하면 된다.
- 말하기 인식(whisper): §7 나중 일로 미룬다. 컴퓨터의 역할은 노출이고, 말하기는 폰이 이미 잘한다.

## 3. 데이터

### 3.1 문장과 상태

입버릇의 모델을 그대로 쓴다.

```
Sentence { id, en, ko, builtin, box, dueAt, spokenCount, createdAt }
```

컴퓨터 쪽에서 더하는 필드(입버릇은 모르는 필드라 무시해도 된다):

```
updatedAt   마지막으로 상태가 바뀐 시각 — 동기화 병합용 (§5)
seenCount   컴퓨터에서 노출된 횟수 — 통계용, 복습 일정에는 쓰지 않는다
typedCount  타이핑 떠올리기 통과 횟수
```

### 3.2 저장 위치

- `<kmd 데이터 폴더>/say/deck.json` — `{format: "sayhabit-deck", version: 1, sentences: [...]}`. 입버릇도 AsyncStorage에 JSON 통째로 둔다. 깨져 있으면 오류만 보이고 덮어쓰지 않는다.
- `<kmd 데이터 폴더>/say/state.json` — 카드 고정, 연습 중인 문장, 최근 3개. 잃어도 되는 화면 상태라 동기화하지 않는다.
- 날짜별 횟수(`days.json`)는 S3로 미뤘다 — 지금은 문장별 누적 횟수(`seenCount`·`typedCount`)만 센다. kmd-core 에는 지역 날짜를 낼 시간 크레이트가 없다.
- 처음 켤 때 입버릇의 기본 문장 40개를 넣는다(`defaultSentences.ts`). 켜진 뒤 처음 읽을 때 파일을 만든다(그 전에는 읽을 때마다 id 가 새로 생긴다). 꺼져 있으면 파일을 만들지 않는다.

### 3.3 기본은 꺼짐

`[say] enabled = false` 가 기본이다. 런처를 다른 사람이 볼 수도 있고, 런처는 검색 도구라는 기대를 깨지 않기 위해서다.
`:say` 를 처음 치면 "런처에 영어 한 줄 보이기를 켤까요?" 항목이 나오고, Enter로 켠다(설정 파일에 기록).

```toml
[say]
enabled = true
card = true            # 런처 한 줄 카드
pass_score = 0.8       # 타이핑 통과 기준
# 아래는 해당 단계에서 추가한다
# voice = true         # S2 — Tab·통과 때 소리
# speech_rate = 1.0
# nudge = false        # S3 — 틈 알림 (켜야 동작)
# start_hour = 9
# end_hour = 22
# per_day = 6
# sync_dir = ""        # S4 — 공유 폴더 (§5)
```

`kmd say on` / `kmd config set say.enabled true` 로도 켠다.

## 4. 복습 일정 — 컴퓨터는 상자를 올리지 않는다

입버릇의 원칙은 "말해야 통과"다. 컴퓨터에서 타이핑으로 맞힌 것을 말한 것과 같게 치면 그 원칙이 무너진다.
그래서 컴퓨터의 결과는 이렇게 반영한다.

| 컴퓨터에서 일어난 일 | 반영 | 입버릇 함수 |
|---|---|---|
| 카드로 봤다 | 아무것도 안 바꾼다 (`seenCount`만 +1) | — |
| 타이핑으로 맞혔다 | 상자는 그대로, 복습만 3시간 뒤로 | `gradeHold` |
| 타이핑으로 틀렸다 | 상자 0, 1시간 뒤 | `gradeFail` |

- 그 결과 컴퓨터에서 자주 본 문장은 폰에서 말할 때 덜 막히고, 상자는 폰에서 말해야만 올라간다.
- 복습 간격은 입버릇과 같다: `[0, 3h, 8h, 1d, 3d, 7d, 14d, 30d]`.

## 5. 폰과 이어 붙이기

지금 입버릇에는 내보내기, 백업, 동기화가 없다(로드맵 3단계에 "진도 백업/복원"이 있다). 그래서 두 단계로 간다.

### 5.1 S1 — 입버릇을 고치지 않고 오늘부터

- 컴퓨터 → 폰: `:say export` 로 "English | 한국어" 줄을 클립보드에 담는다. 폰의 입버릇 문장 탭 일괄 붙여넣기에 그대로 붙인다. 문장만 넘어가고 진도는 안 넘어간다.
- 폰 → 컴퓨터: 같은 형식을 `:say import` 로 받는다. 이미 있는 영어 문장은 건너뛴다.
- 두 앱은 따로 진도를 가진다. 문장 목록만 맞춘다.

### 5.2 S4 — 공유 폴더로 진도까지

손버릇 통계의 기기 간 비교와 같은 방식이다. 서버를 두지 않는다는 입버릇의 원칙을 지킨다.

- 공유 파일: `<sync_dir>/sayhabit/deck.v1.json` (iCloud Drive, OneDrive 등 사용자가 고른 폴더).
- 형식: §3.1의 `Sentence` 배열 + `{ "format": "sayhabit-deck", "version": 1 }` 머리. 이 형식은 입버릇 로드맵 3단계의 백업 형식과 **같은 것**으로 정한다. 한 번 정해 두면 백업과 동기화가 한 기능이 된다.
- 병합은 둘로 나눈다.
  - **문장 내용**(`en`, `ko`, 삭제 여부): 문장 `id` 별로 `updatedAt` 이 늦은 쪽이 이긴다.
  - **진도**(`box`, `dueAt`): 상태를 덮어쓰지 않고 **채점 기록**을 합친다. 기기마다 `{id, at, grade: pass|hold|fail, device}` 를
    `<sync_dir>/sayhabit/log-<기기>.jsonl` 에 덧붙이고, 읽을 때 모든 기기의 기록을 시각순으로 SRS 함수에 다시 돌려 상태를 낸다.
  - 상태를 덮어쓰면 안 되는 이유: 컴퓨터가 폰의 통과 기록을 받기 전에 hold를 하면, 시각만 늦다는 이유로 폰에서 올린 상자를 지운다.
    기록을 다시 돌리면 "폰 pass → 컴퓨터 hold" 순서대로 반영돼 상자가 남는다.
  - 기기마다 자기 파일에만 쓰므로 공유 폴더의 동시 쓰기 충돌이 없다(손버릇 통계 스냅숏과 같은 이유).
  - 30일 지난 기록은 문장별 상태 하나로 접어 `deck.v1.json` 에 넣고 지운다.
- 지운 문장: `deletedAt` 을 남기고 30일 뒤에 실제로 지운다. 안 그러면 한쪽에서 지운 문장이 다른 쪽에서 되살아난다.
- 입버릇 쪽 작업(그쪽 저장소에서 따로): 내보내기/가져오기 버튼, `updatedAt`·`deletedAt` 필드, iOS 파일 앱의 iCloud Drive 폴더 읽기·쓰기.

| `:say` 명령 | `query_prefix.rs`, `kmd-desktop/src/app/say.rs` | `:prompt` 처럼 미리보기 → Enter 확정 |
| 런처 카드 | `kmd-desktop/src/app/say.rs`, `view.rs` 상태 줄 | 목록 아래 한 줄, 빈 입력 Tab |
| 연습 | `kmd-core/src/say/command.rs` | 새 화면 없이 입력창 그대로 — `:say <답>` 미리보기, Enter 확정 |
| 소리 | `kmd-core/src/say/voice.rs` | `say` / SAPI, `hide_console()` 필수(audit) |
| 틈 감지 | `kmd-daemon` 키 훅 | 마지막 키 시각만 본다. 무엇을 쳤는지는 보지 않는다 |
| CLI | `kmd say list|add|import|export|stats|rm|on|off` | 연습은 런처에서. TUI는 `:say` 를 그대로 지원(정답 열기는 상태 줄) |

- 순수 TS 모듈을 옮길 때 입버릇의 `tests/logic.test.ts` 기대값을 Rust 테스트로 그대로 옮긴다. 같은 입력이면 폰과 컴퓨터의 점수가 같아야 한다.
- 새 크레이트 의존성은 없다.

## 7. 단계

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| **S1** | core 이식(srs·scoring·bulk·plan) + deck 저장 + `:say` 목록·추가·import·export + 타이핑 연습 + 런처 카드 | 런처를 열 때마다 문장이 보이고, `:say export` 결과가 폰 입버릇에 그대로 붙는다 |
| **S2** | 소리(macOS `say`, Windows SAPI) | 카드 Tab과 연습 통과 때 소리가 난다 |
| **S3** | 틈 알림(데몬 틈 감지 + 데스크톱 구석 카드) | 일주일 써 보고 "끊긴다"는 느낌이 없을 것. 있으면 기준(5분/60초/45분)을 조정 |
| **S4** | 공유 폴더 동기화 + 입버릇 백업 형식 확정 | 폰에서 통과한 문장이 컴퓨터 카드에서 떠올리기 단계로 보인다 |
| 나중 | whisper 말하기, dojo "영어 수련" 과, 문장 묶음(덱) | — |

S1이 가장 많이 쓰일 부분이다. 런처 카드 하나만으로 하루 수십 번 노출이 생긴다.

## 8. 잘 되고 있는지 보는 법

S1은 `kmd say stats` / `:say stats` 의 누적 횟수로 본다. 날짜별은 S3부터 `days.json` 으로.

- 하루 노출 수(카드 + 틈 알림)
- 타이핑 떠올리기 통과율
- S4 이후: 컴퓨터에서 많이 본 문장과 적게 본 문장의 폰 첫 통과율 차이 — 노출이 실제로 말하기를 돕는지 확인하는 숫자

## 9. 정한 것과 이유

| 결정 | 이유 |
|---|---|
| 컴퓨터는 노출, 폰은 말하기 | 컴퓨터에서 소리 내어 말하게 하면 일과 회의를 끊는다 |
| 카드는 목록 항목이 아니라 아래 한 줄 | Enter로 최근 항목을 여는 습관을 깨지 않는다 |
| 컴퓨터 결과는 상자를 올리지 않는다 | 입버릇의 "말해야 통과" 원칙을 지킨다 |
| 기본 꺼짐 | 런처는 검색 도구이고, 화면을 다른 사람이 볼 수 있다 |
| OS 내장 음성, 저절로 소리 내지 않음 | 새 의존성이 없고, 사무실 기본값으로 안전하다 |
| 틈 알림은 시스템 알림 대신 자체 카드 | 데몬은 앱 번들이 아니라 알림 출처와 권한이 꼬인다 |
| 동기화 형식 = 입버릇 백업 형식 | 백업과 동기화를 한 번에 해결하고, 서버를 두지 않는다 |
| 명령은 `:say` (+ `:입버릇`) | 영문 자판에서 한영 전환 없이 친다 |
