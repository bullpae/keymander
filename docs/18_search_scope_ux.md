# 검색 범위(Scope) 관리 UX 설계

> 상태: **S1 구현 (2026-10-19, Unreleased)** — `:scope` 목록·자동완성·추가·제거(되돌리기)·즉시
> 인덱싱, 합산 의미(`include_user_folders`·`use_default_ignores`) + 레거시 해석, 입구 E1·E3·E4·E5,
> TUI 동등 지원, CLI `kmd scope`(E8). **결정**: 명령 `:scope`(별칭 `:dirs`), 프로그램 폴더의 하위
> 폴더는 숨김(S2), 기본 제외 규칙은 `use_default_ignores`, E1은 S1에 포함. 남은 것: S2(폴더 종류
> `apps`·폴더별 깊이·할당량 분배·E2), S3(부분 인덱싱 진행률·드래그 앤 드롭·첫 실행 안내).
> 배경: 포터블 프로그램 폴더(`D:\Util`)와 작업 폴더를 따로 두는 사용자는, 그 폴더를
> 검색 범위에 넣지 않으면 keymander를 런처로 쓸 수 없다. 지금은 `config.toml`을 손으로
> 고쳐야 하고, 고친 뒤에도 데몬 재시작이나 인덱스 리빌드를 직접 해야 한다.

## 1. 지금 무엇이 불편한가 (2026-10-19 실사용 기록)

`D:\Util`을 검색되게 만드는 데 실제로 거친 단계:

1. 설정 파일 위치 찾기 (`kmd config path`)
2. `search_paths`를 적으면 **기본 폴더(문서·다운로드·OneDrive)가 사라진다**는 걸 코드를
   읽고 알아내서, 기본 폴더를 손으로 다시 적기
3. 지정 폴더 할당량(`max_results / 2` = 2,500)에 걸려 exe가 잘릴 수 있다는 걸 알아내고
   `max_results` 올리기
4. `kmd index --rebuild` 후 **데몬 재시작** (데몬 메모리의 인덱스는 그대로라서)
5. `.cat`·`.SF`·dll 같은 부속 파일이 섞여 `ignore_patterns`를 적었더니 **기본 제외 목록도
   사라져서** 기본값 30여 개를 손으로 옮겨 적기
6. 그래도 `vera`를 치면 exe보다 폴더가 먼저 나옴 (v0.17.0에서 실행 이력 쪽만 보정)

이미 있는 장치와 그 한계:

| 장치 | 위치 | 한계 |
|---|---|---|
| `?` 빈 질의 → 폴더 제안, Enter로 추가 | `folder_suggest.rs` | 제안된 폴더만 추가할 수 있다. 원하는 폴더를 직접 지정할 수 없다. 추가해도 "다음 인덱스 갱신부터 반영"(최대 6시간) |
| 검색 결과가 0건일 때 폴더 제안 2개 | `search_routing.rs` | 위와 같음 |
| TUI F2 설정의 목록 편집 | `src/tui/settings` | TUI에만 있음. 데스크톱 `:set`에는 범위 항목이 없음 |
| `:f /경로 질의` | `folder_search.rs` | 일회성 검색. 그 폴더를 범위에 넣는 길로 이어지지 않음 |
| `config.toml` 직접 편집 | — | 위 1~5단계 |

**근본 원인 세 가지:**

- **(A) 범위가 눈에 안 보인다.** 지금 어떤 폴더가 검색되는지 런처 안에서 볼 방법이 없다.
- **(B) 추가해도 바로 반영되지 않는다.** 추가 → 리빌드 → 데몬 재로드가 끊겨 있다.
- **(C) 설정 의미가 "추가"가 아니라 "대체"다.** `search_paths`·`ignore_patterns`를 적는 순간
  기본값이 사라진다. 손으로 고치는 사람에게는 함정이다.

추가로, 포터블 프로그램 폴더는 문서 폴더와 성격이 다르다:

- **(D) 프로그램 폴더는 exe만 필요하다.** dll·리소스·언어 파일은 잡음이고, 폴더명과
  exe명이 같아 폴더가 exe를 이긴다(종류 가중치: 폴더 80, 파일 50).

## 2. 설계 원칙

1. **런처 안에서 끝낸다.** 설정 파일을 열지 않고 추가·삭제·확인까지 한다.
2. **키보드가 기본이고 마우스는 보조다.** 경로 자동완성이 주 경로이고, 드래그 앤 드롭은 보조.
3. **추가하면 바로 검색된다.** 진행 상황은 상태줄에 보인다.
4. **발견 가능해야 한다.** 범위 관리 화면에 들어가는 입구가 여러 곳에 있어야 한다(§4).
5. **되돌릴 수 있다.** 삭제는 확인창 대신 되돌리기(undo)로 처리한다. 런처의 속도감을 해치지 않기 위해서다.
6. **기존 설정을 깨지 않는다.** 이미 `search_paths`를 적어 둔 사용자의 동작은 그대로 둔다(§5.3).

## 3. 핵심 화면 — `:scope` (검색 범위)

새 `:` 명령. `query_prefix::COMMANDS`에 등록한다. 별칭은 `:scope`, `:dirs`로 하고,
이름은 §8에서 결정한다.

### 3.1 목록 (`:scope` 입력 직후)

```
┌──────────────────────────────────────────────────────────────┐
│ :scope                                                        │
├──────────────────────────────────────────────────────────────┤
│ ➕ 폴더 추가…   경로를 입력하세요 (예: :scope D:\Work)         │
│ 📦 D:\Util            프로그램 · 깊이 4 · 실행 파일 99개 · 3분 전  │
│ 📁 D:\Work            문서     · 깊이 6 · 2,310개 · 3분 전     │
│ 📁 문서               기본     · 깊이 4 · 85개                 │
│ 📁 다운로드           기본     · 깊이 4 · 30개                 │
│ ☁ OneDrive           기본     · 깊이 4 · 6개                  │
│ ─ 제외 규칙: 폴더 37개 · 확장자 8개   (Enter: 편집)             │
├──────────────────────────────────────────────────────────────┤
│ Enter 열기   Ctrl+Del 제거   Ctrl+T 종류   Ctrl+←/→ 깊이       │
└──────────────────────────────────────────────────────────────┘
```

- 행마다 **종류 · 깊이 · 인덱싱된 항목 수 · 마지막 갱신 시각**을 보여 준다. (A)를 해결한다.
- 기본 폴더(OS가 알려 주는 문서·다운로드 등)는 `기본` 배지를 붙여 구분한다. 기본 폴더를 제거하면
  "숨김"으로 처리한다(§5.3).
- 상세 패널의 컨텍스트 액션은 기존 Ctrl+N 체계를 그대로 따른다:

| 키 | 액션 |
|---|---|
| Enter / Ctrl+1 | 탐색기에서 열기 |
| Ctrl+2 | 이 폴더만 지금 다시 인덱싱 |
| Ctrl+3 | 경로 복사 |
| Ctrl+T | 종류 전환: 문서 ↔ 프로그램 (§5.2) |
| Ctrl+← / Ctrl+→ | 깊이 −1 / +1 (1~8) |
| Ctrl+Del | 범위에서 제거 → 상태줄에 "제거됨 · Ctrl+Z 되돌리기" (5초) |

### 3.2 추가 — 경로 자동완성

`:scope ` 뒤에 경로를 치면 결과 목록이 **폴더 자동완성**으로 바뀐다. 폴더 나열은
`folder_search::list_dir`를 재사용한다(상한 5천 개, 숨김 규칙 공유).

```
┌──────────────────────────────────────────────────────────────┐
│ :scope d:\ut                                                  │
├──────────────────────────────────────────────────────────────┤
│ ➕ D:\Util 추가        프로그램 폴더로 보입니다 (실행 파일 99개)     │
│ 📁 D:\Util\…           Tab: 하위 폴더로 들어가기               │
│ 📁 D:\Utility_old                                              │
└──────────────────────────────────────────────────────────────┘
```

- **Tab**은 선택한 폴더 경로로 입력을 채우고 그 하위를 보여 준다(셸 자동완성과 같은 감각).
  **Enter**는 추가한다.
- 대소문자와 구분자(`/`·`\`)를 정규화한다. 이미 범위 안에 있는 경로(하위 폴더 포함)는
  "이미 D:\Util 범위에 포함됨"으로 안내하고 중복 추가를 막는다.
- 추가하기 전에 폴더를 가볍게 미리 살펴(상위 2단계, 항목 상한) **종류를 자동으로 추천**한다:
  exe·lnk 비율이 높으면 `프로그램`, 아니면 `문서`(§5.2). 추천은 기본 선택일 뿐이고, 추가한 뒤
  Ctrl+T로 바꿀 수 있다.
- `~`, `%USERPROFILE%`, 드라이브 문자만 친 경우(`d:`)도 받는다.

### 3.3 추가 직후 피드백 — 즉시 인덱싱 (B)

```
상태줄:  ⏳ D:\Util 인덱싱 중… 1,204개
      →  ✅ D:\Util 추가됨 — 실행 파일 99개 검색 가능
```

- 데스크톱이 config를 저장한 뒤 데몬에 **IPC로 해당 폴더만 인덱싱하라고 요청**한다.
  데몬이 없으면 데스크톱이 직접 빌드한다(기존 `spawn_full_engine_load_task` 경로).
- 1단계는 기존 `Request::RebuildIndex`로 충분하다. 실측상 전체 리빌드가 1초 안쪽이다
  (2026-10-19 `D:\Util` 포함 835ms). 2단계에서 `Request::IndexPaths { paths }`로 부분 갱신한다(§6).
- 끝나면 데몬이 새 인덱스를 공유 캐시에 쓰고, 데스크톱은 엔진을 다시 불러온다.
  지금은 `kmd index --rebuild`를 해도 데몬 메모리가 갱신되지 않아 재시작이 필요하다(1단계 3번).
  이 끊김도 함께 없앤다.

## 4. 입구 — 범위 관리를 어디서 발견하나

`:scope`를 모르는 사용자도 자연스럽게 닿게 한다. 모두 같은 코어 함수(`scope::add`)를 부른다.

| # | 입구 | 동작 | 비용 |
|---|---|---|---|
| E1 | **경로를 직접 입력** (`D:\Util`) | 입력이 범위 밖의 절대 폴더 경로면 결과 맨 위에 `➕ D:\Util 을 검색 범위에 추가` 행 | 낮음 |
| E2 | **폴더 결과의 컨텍스트 액션** | 범위 밖 폴더(`:f` 결과, 경로 탐색)에 "검색 범위에 추가" 표시. 범위 안 항목에는 "이 폴더 제외"(→ ignore 규칙) | 낮음 |
| E3 | **`:set` 첫 행** | `검색 범위: 폴더 5개 · 5,185 항목` → Enter로 `:scope` 진입 | 매우 낮음 |
| E4 | **결과가 0건일 때** | 지금의 폴더 제안 위에 `:scope로 폴더 추가하기` 안내 행 | 매우 낮음 |
| E5 | **`?` 폴더 제안** | 기존 그대로. 추가 후 §3.3 즉시 인덱싱이 적용된다 | 없음 |
| E6 | **드래그 앤 드롭** | 탐색기에서 폴더를 런처 창에 끌어다 놓으면 추가 확인 행 | 중간 (iced 창 이벤트 `FileDropped`) |
| E7 | **첫 실행 온보딩** | 첫 실행 때 한 번: "자주 쓰는 프로그램·작업 폴더가 있나요? `:scope`" | 낮음 |
| E8 | **CLI** | `kmd scope add D:\Util --apps`, `kmd scope rm`, `kmd scope list` | 낮음 |

E1·E2가 "보고 있던 폴더를 그 자리에서 넣는" 가장 직관적인 경로이고, E3·E4는 발견성을 담당한다.

## 5. 데이터 모델

### 5.1 설정 스키마

```toml
[launcher]
# OS 기본 사용자 폴더(바탕 화면·문서·다운로드·OneDrive)를 범위에 포함
include_user_folders = true

# 추가 폴더 — 기본 폴더와 "합쳐진다" (대체가 아님)
search_paths = ["D:\\Util", "D:\\Work"]

# 폴더별 옵션 (없으면 전역 search_depth, kind = "files")
[launcher.folders."D:\\Util"]
kind = "apps"      # apps | files
depth = 4

[launcher.folders."D:\\Work"]
depth = 6
```

- 폴더별 옵션은 `search_paths`(경로 목록)와 분리한 맵으로 둔다. 기존 `search_paths`
  문자열 배열을 그대로 쓸 수 있어 하위 호환이 쉽고, 옵션이 없는 폴더는 한 줄로 끝난다.
- `ignore_patterns`·`ignore_extensions`도 같은 문제(C)가 있다. **"기본값 + 사용자 추가"**
  구조로 바꾼다: `ignore_patterns_extra = [...]`를 두거나, `ignore_patterns`를 그대로 두고
  `use_default_ignores = true`를 추가한다. 이번 설계에서는 후자를 권장한다(§5.3과 같은 규칙).

### 5.2 폴더 종류 — `apps` (D)

포터블 프로그램 폴더를 위한 모드:

- **실행 가능한 것만 인덱싱한다**: `exe`, `lnk`, `bat`, `cmd`, `ps1`, `ahk`, `msc`.
  macOS는 `.app` 번들, Linux는 실행 비트가 선 파일.
- 이 항목들은 `ItemKind::App`으로 등록한다. 가중치 70을 받아 폴더(80)와 거의 같은 선에서
  시작하고, 프로그램 폴더의 하위 폴더는 **인덱싱하지 않는다**. 그러면 `vera`의 1위가
  `VeraCrypt.exe`가 된다.
- **설치·보조 실행 파일은 걸러 낸다**: `unins*.exe`, `*crashpad*`, `*updater*`, `*helper*`
  같은 기본 제외 규칙을 둔다(설정으로 덮어쓸 수 있음).
- **변형 실행 파일 이름은 정리한다**: `VeraCrypt-x64.exe`·`VeraCrypt-arm64.exe`처럼 같은 폴더에
  변형이 여럿이면 현재 아키텍처에 맞는 하나를 대표로 올리고 나머지는 점수를 낮춘다. 이 항목은 2단계에서 검토한다.
- 표시 이름은 exe 메타데이터의 `FileDescription`을 쓸 수 있다("Flow.Launcher.exe" →
  "Flow Launcher"). 이미 앱 아이콘 추출 경로(`app_icons.rs`)가 있으니 그쪽과 함께 검토한다.

`files`(기본)는 지금과 같다. 파일과 폴더를 모두 인덱싱하고, 전역 제외 규칙을 따른다.

이 모드가 생기면 지난번에 손으로 적은 `ignore_patterns`(plugins·jre…)와 `ignore_extensions`
(dll·cat…)의 대부분이 필요 없어진다. 프로그램 폴더는 애초에 exe만 보기 때문이다.

### 5.3 하위 호환 (기존 동작 보존)

| 기존 config 상태 | 새 해석 |
|---|---|
| `search_paths` 키 없음 | `include_user_folders = true`, 추가 폴더 없음 → **지금과 같음** |
| `search_paths` 키 있음, `include_user_folders` 키 없음 | **레거시**: `include_user_folders = false`로 해석 → 적어 둔 목록만 쓴다(지금과 같음) |
| 새로 `:scope`로 추가 | `include_user_folders = true`를 명시해 저장하고 추가 폴더만 `search_paths`에 적는다 |

- 레거시 사용자가 `:scope`를 처음 열면 기본 폴더가 이미 `search_paths`에 들어 있을 수 있다.
  이 경우 기본 폴더 경로를 자동으로 `기본` 배지로 묶어 보여 준다(경로 비교로 판별). 지금의
  사용자 설정이 바로 이 경우다.
- 기본 폴더를 `:scope`에서 제거하면 `hidden_user_folders = ["다운로드"]`처럼 숨김 목록에 남긴다.
  이렇게 해야 OS가 위치를 바꿔도(OneDrive 리디렉션) 의도가 유지된다.

### 5.4 할당량

지정 폴더 스캔 상한(`max_results / 2`)에 걸려 **나중에 적은 폴더가 잘리는 문제**(1단계 3번)를 고친다:

- 폴더마다 공정하게 나누거나(폴더당 최소 보장), `apps` 폴더는 항목 수가 적으니 상한 계산에서 뺀다.
- 잘렸으면 `:scope` 행에 `⚠ 2,500개에서 잘림 — 깊이를 줄이거나 제외 규칙 추가`를 보여 준다.
  지금은 조용히 잘린다.

| 단계 | 내용 | 해결 | 규모 |
|---|---|---|---|
| **S1** | `:scope` 목록·추가(경로 자동완성)·제거(undo) · `:set` 첫 행(E3) · 0건 안내(E4) · 추가 후 즉시 리빌드(`RebuildIndex` IPC → 데스크톱 엔진 재로드) · `include_user_folders` 합산 의미 + 레거시 해석 | A·B·C | 중 |
| **S2** | 폴더 종류 `apps` + 폴더별 깊이 · 종류 자동 추천 · 할당량 공정 분배 + 잘림 경고 · E1(경로 입력)·E2(컨텍스트 액션) | D | 중 |
| **S3** | `Request::IndexPaths` 부분 인덱싱 + 진행률 · 드래그 앤 드롭(E6) · CLI `kmd scope`(E8) · TUI F2 화면을 같은 코어로 교체 · 온보딩(E7) · `use_default_ignores` | 마감 | 중 |

- 코어 로직(경로 정규화·중복/포함 판정·저장·레거시 해석)은 `kmd-core::scope` 모듈에 둔다.
  데스크톱·TUI·CLI는 화면만 담당한다. 지금 `folder_suggest::execute_suggest_action`의 저장
  로직도 여기로 옮긴다.
- 저장은 기존 `Config::update_and_save`를 쓴다. 다른 곳에서 바꾼 설정을 덮지 않고, 주석도 보존한다.
- 테스트: 레거시 해석 표(§5.3) 전 케이스, 포함 판정(대소문자·구분자·하위 폴더),
  `apps` 모드에서 `vera` 1위가 exe인지, 할당량 분배.

## 7. 검토했지만 택하지 않은 것

| 안 | 이유 |
|---|---|
| 네이티브 폴더 선택 대화상자(`rfd`) | 키보드 흐름이 끊기고 런처 창 포커스가 꼬인다. 의존성도 늘어난다. 경로 자동완성과 드래그 앤 드롭으로 대체한다. 수요가 있으면 `:scope` 행에 "찾아보기…"로만 추가 |
| 드라이브 전체 자동 스캔 기본 켜기 | `scan_drives`가 이미 있지만 잡음이 많고 느리다. "원하는 폴더만" 원칙에 반한다 |
| 자주 쓰는 폴더 자동 추가 | `folder_suggest`가 "자동 추가 금지, 제안만"으로 정한 원칙(docs/15 P2)을 유지 |
| 별도 설정 창(GUI 폼) | 런처는 입력창 하나와 결과 목록으로 구성된다. 기존 `:set`·`:prompt`·`:keymap`과 같은 "명령 + 목록 + 컨텍스트 액션" 패턴이 일관된다 |

## 8. 결정이 필요한 것

1. **명령 이름**: `:scope` / `:dirs` / `:folders` / 한글 별칭 병행 여부
2. **`apps` 모드에서 하위 폴더를 아예 숨길지**: 숨기면 `vera`가 깔끔해지지만 "D:\Util\VeraCrypt
   폴더 열기"는 `:f`나 경로 입력으로만 가능해진다
3. **기본 제외 규칙 구조**: `use_default_ignores = true`(권장)와 `ignore_patterns_extra` 중 선택
4. **S1 범위에 E1(경로 입력 → 추가 행)을 당겨 넣을지**: 비용이 낮고 체감이 크다

## 9. macOS 패키지(번들) 처리 — 구현 (2026-10-19, Unreleased)

> 구현: `index/package.rs`(판정) · `files.rs`(walkdir 두 곳 자식 차단 + 항목화
> `apply_package_kind`) · `index/mod.rs`(외부 프로바이더 사후 필터) · `content_index::walk_entries`
> · `scope::count_executables`. 테스트는 `package::test_force`로 모든 OS에서 macOS 분기를 돌린다.
> **실기기 미검증** — 9.5 실기기 항목이 남았다.

### 9.1 문제

macOS 앱은 파일이 아니라 `Foo.app` **폴더**다. Finder는 이런 "패키지" 폴더를 파일 하나처럼
보여 주지만, 파일 스캐너(`index/files.rs`의 walkdir)는 일반 폴더로 보고 안으로 내려간다.

- `Foo.app`이 **폴더(Directory)** 로 등록된다. Enter는 `open`이라 실행은 되지만 아이콘·종류·이름
  (`Foo.app`)이 앱이 아니다.
- 번들 안의 `Contents/Info.plist`, `MacOS/Foo`, `Resources/*.icns`, `*.lproj/…`, `Frameworks/…`가
  `search_depth`(기본 4)까지 통째로 들어간다. 앱 하나에 수백~수천 개다. `foo`를 치면 이런 내부 파일이
  결과에 섞이고, 지정 폴더 할당량(`max_results / 2`)을 먹어 정작 다른 파일이 잘린다.
- 앱만 그런 게 아니다. `.pages`·`.numbers`·`.key`·`.rtfd` 문서도 패키지이고, `~/Pictures`를 범위에 넣으면
  `Photos Library.photoslibrary` 안의 수십만 개 파일이 쏟아진다.

Windows의 dll·리소스 잡음(1장 5번)과 같은 성격인데, macOS는 "번들 단위로 보면 된다"는 정답이 있다.

### 9.2 방향 — 패키지는 원자(atom)로 본다

스캔하다가 패키지를 만나면 **그 폴더 하나만 항목으로 넣고 안으로는 내려가지 않는다**.

| 패키지 | 등록 | 근거 |
|---|---|---|
| `.app` | **앱(App)**, 이름은 `.app`을 뗀 `Foo`, 아이콘은 기존 `app_icons.rs`의 Info.plist→icns 경로 | `index/apps.rs`가 `/Applications`에서 만드는 항목과 같은 모양 — 같은 경로면 경로 중복 제거로 하나만 남는다 |
| 문서 패키지 `.pages` `.numbers` `.key` `.rtfd` | **파일(File)** — `open`이 기본 앱으로 연다 | 사용자에겐 문서 하나 |
| 라이브러리 `.photoslibrary` `.musiclibrary` `.tvlibrary` `.imovielibrary` `.fcpbundle` | 파일 하나로 (안은 절대 안 들어감) | 내부를 건드리면 안 되는 앱 전용 저장소 |
| 개발·시스템 `.framework` `.bundle` `.plugin` `.kext` `.appex` `.xcodeproj` `.xcworkspace` `.dSYM` `.sparsebundle` 등 | 파일 하나로 | 실행 대상은 아니지만 "그런 게 있다"는 찾을 수 있게 |

**판정** — 코어(`kmd-core`)에는 Objective-C 의존성이 없으므로 시스템 API(UTType의 `com.apple.package`)
대신 다음을 쓴다.
1. 위 표의 확장자 목록. 단 **`.app`은 `Contents/Info.plist`가 있을 때만** 번들로 본다 — 개발자 소스 폴더
   이름이 `web.app`인 경우를 앱으로 오판하지 않기 위해서.
2. 목록에 없는 확장자라도 `Contents/Info.plist`가 있으면 번들로 본다(서드파티 패키지 대비).

**적용 범위** — macOS에서만(`cfg!(target_os = "macos")`). 판정 함수 자체는 OS와 무관하게 테스트한다.

### 9.3 고칠 곳

| 위치 | 변경 |
|---|---|
| `index/files.rs` walkdir 두 곳(지정 폴더 우선 스캔, 홈 일반 스캔) | `filter_entry`에서 패키지의 **자식**을 막고, 패키지 자신은 위 표대로 항목화 (`walkdir_into_items`에 패키지 분기) |
| `index/mod.rs` 빌드 끝 | 외부 프로바이더(fd·locate 등) 결과에서 **경로 중간에 패키지가 끼인 항목**을 거른다 — `ignore_extensions` 사후 필터와 같은 자리. Spotlight(mdfind)는 이미 패키지를 제대로 다루지만 같은 필터를 거쳐도 무해 |
| `content_index::walk_entries` | 패키지 안으로 내려가지 않는다 (본문 인덱스가 번들의 plist·strings를 색인하지 않게) |
| `folder_suggest` 활동 스캔 | 같은 순회를 쓰므로 함께 해결 — 앱이 자기 번들 안에 쓰는 캐시가 "활동이 많은 폴더"로 오판되지 않는다 |
| `scope::count_executables` | 이미 `.app`을 하나로 센다 (2026-10-19 반영) — 9.2의 판정 함수로 교체 |

### 9.4 S2 "프로그램 폴더" 모드와의 관계

9장은 **모든 폴더**에 적용하는 버그 수정이다. S2의 `apps` 모드는 그 위에서 "실행할 수 있는 것만"
남긴다. macOS 기준 실행 가능 = `.app` 번들 + 실행 권한 비트가 있는 파일 + `.command`·`.sh`.
PATH 실행 파일 수집(`index/path.rs`)도 지금은 권한 비트를 보지 않으므로 같은 판정 함수로 맞춘다.

### 9.5 검증

- 단위 테스트(모든 OS): 가짜 번들(`Foo.app/Contents/Info.plist`, `Doc.pages/…`, Info.plist 없는 `web.app`)
  으로 판정·항목화·자식 차단을 확인.
- macOS CI(macos-latest)에서 같은 테스트가 실제 플랫폼 분기로 돈다.
- 실기기: `~/Applications`나 포터블 앱 폴더를 `:scope`로 추가 → 앱 아이콘으로 하나씩, 내부 파일 0개.
  `~/Pictures` 추가 시 사진 보관함이 항목 하나인지.
